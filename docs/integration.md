# 按工作流引用和组合

本合集把上游仓库映射到任务、交付物和评审决策。引用意味着找到适用的能力与来源；不意味着已经安装、互相兼容、完成 SSO 集成或通过生产验收。

## 建议的最小组合

| 当前情境 | 可从哪组开始 | 应形成的闭环 |
| --- | --- | --- |
| 个人验证一个产品想法 | PM Skills 或 Product Manager Skills 选一项；Excalidraw 或 Penpot 选一个；需要实现时再接 Spec Kit 或 OpenSpec | 问题证据 → 范围 → 可操作原型/实现 → 实际验证；先不引入全套企业平台 |
| 已有团队迭代一个功能 | 复用现有文档与工单；必要时参考 Plane / OpenProject / Taiga；用 ADR 记录重要变更，Playwright 验证核心路径 | 需求与现有问题 → 变更任务 → 相关评审 → 验收 → 发布结果 |
| 面向企业的正式交付 | 现有权限与交付链；ASVS、可访问性和 AI 风险工具按风险选用；发布开关与监控按实际依赖补足 | 需求与合同约束 → 有责任人的评审 → 真实测试 → 可观察发布与回滚 |
| 上线后判断是否继续投入 | PostHog / Umami 解决适用的事件观察；Metabase / Superset 选一个分析层；实验需要时加 GrowthBook | 指标含义 → 数据 → 决策 → 调整或停止；不以新增图表代替结果 |

一组中的“或”表示替代关系，不要求全部安装。组件库、白板和协作套件也不应为凑完整而同时引入。

## 接入 Agent Skills

1. 确定任务和产物，例如访谈整理、需求评审或发布检查。
2. 打开该仓库 README，核对当前 Agent 支持方式、技能目录、许可和执行行为。使用上游当前说明，不假设不同项目有同一安装命令。
3. 选择一项适合的技能，明确输入证据、输出位置、范围与授权。方法中的示例、角色、分类不是产品必须实现的功能。
4. 将结果与真实材料核对；AI 评审是建议，运行检查和公司批准需分别记录。
5. 若要把上游内容复制进自有 skill，记录来源、版本与许可证，保留必要署名；引用链接不等于取得重新分发许可。

这与将几十套 skill 全部导入默认上下文不同：按任务加载可以减少冲突，并使结果可追溯。本合集不修改本机 skill，也不影响已有 RED Skill 发布版本。

## 接入可运行软件与代码库

先区分三类交付：研究评估、试用部署、正式集成。目录条目只完成了公开元数据与 README 核验，尚未逐个部署。正式选型时检查现有替代品、社区版功能、存储与用户数据、授权、升级和运维成本，并用一条完整用户路径验证。

UI 库可以复用真正需要的组件；监控软件检查的是部分运行信号；原型工具展示的是设计或模拟交互。不要把其中一种证据当作另一种能力已成立。
